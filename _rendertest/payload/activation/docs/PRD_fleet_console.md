## 1. 产品目标

本期交付两件事：
1. **外网客户端集群（fleet）管理能力**——在现有 `/api/heartbeat` 与 license 体系之上，扩展心跳协议、构建客户端/打印机聚合视图、异常授权发现与远程管控指令通道，并以 **500 台客户端** 为规模前提设计。
2. **控制台合并与美化**——将 `console.html` 与 `admin.html` 合并为单一控制台，套用 `config.html` 已落地的专业后台风格，并把服务端配置中心并入「配置」Tab；打印机状态由客户端上报、服务端只读展示 + 远程管控，不下发打印机配置。

## 3. 需求池（P0 / P1 / P2）

> 优先级定义：**P0** 本期必须交付；**P1** 应交付（协议须定义全，实现可部分模拟）；**P2** 增强/可后置。
> 拆分两大块：**A. 外网客户端集群管理（fleet）** ｜ **B. 页面合并与美化**。

### A. 外网客户端集群管理（fleet）

#### A1 心跳协议扩展　【P0】
- **描述**：扩展现有 `POST /api/heartbeat`（当前接收 `machine_id/code/nonce`，记录 `{at,code,valid,reason,nonce}`，可返回 `reason:'revoked'` 让客户端降级）。新增客户端自报字段：`online(bool)`、`version(string)`、`public_ip(string)`、`region(string)`、`cpu_usage(0-1)`、`mem_usage(0-1)`、`boot_time(unix s)`、`client_ts(unix s)`；并在心跳体携带 `printers[]`（每台：`printer_id, name, status[online|offline|paper_out|jam|...], paper_level?, ink_level?, last_print_at?`）。服务端 `store.recordHeartbeat` 须持久化这些字段；返回体保持 `{ok,valid,reason,server_time}` 兼容；`revoked` 时仍返回 `reason:'revoked'`。
- **验收标准**：
  1. 新字段缺失时服务端不报错，旧客户端仍可正常心跳（向后兼容）。
  2. 服务端按 `machine_id` 保存「最新快照 + 最近 N 条历史」（沿用最多 50 条上限）。
  3. `printers[]` 被纳入客户端快照，可被 A2 列表/详情读取。
  4. 上报字段可在「集群」列表/详情中展示。

#### A2 Fleet API　【P0】
- **描述**：
  - `GET /api/admin/fleet/clients`：分页（`page,pageSize`）、筛选（`status: online|offline|abnormal`、`version`、`region`）、搜索（`machine_id/qq/code` 模糊）。返回 `{items, total, page, pageSize, agg:{online,offline,abnormal,total}}`。
  - `GET /api/admin/fleet/clients/:machine_id`：详情，含心跳历史、客户端快照字段、`printers[]`、license 信息（`code/plan/expires_at/status`）、最近异常标记。
  - `GET /api/admin/fleet/printers`：跨客户端聚合打印机视图，每项 `{printer_id, name, client_machine_id, client_version, status, paper_level?, ink_level?, last_print_at?, online}`；支持按状态/客户端筛选与搜索。
- **验收标准**：
  1. 500 台数据下 `clients` 列表响应 < 500ms（分页/聚合在服务端内存索引完成）。
  2. 筛选 + 搜索组合正确，`total` 准确。
  3. 打印机聚合能唯一定位「哪台客户端挂着哪台打印机」。

#### A3 异常授权发现（anomaly）　【P0】
- **描述**：基于心跳历史与 license 记录做规则检测，阈值存入 `configManager`：
  - `code_shared`：同一 `code` 在 ≥N 台不同 `machine_id` 出现有效心跳。
  - `expired_online`：`license` 已过期（`expires_at < now`）但客户端仍有效心跳。
  - `machine_mismatch`：心跳 `reason='machine-mismatch'`（机器码被篡改）。
  - `long_offline`：最后心跳距 `now > T` 秒（如 > 7 天）。
  - `freq_anomaly`：心跳频率偏离设定区间（过快/过慢）。
  - 提供 `GET /api/admin/fleet/anomalies`（列表 + 命中规则 + 严重级别）；处置接口：`POST .../anomalies/:id/revoke`（吊销对应 license，复用现有 `disable→revoked`，客户端下次心跳降级）、`POST .../anomalies/:id/blacklist`（拉黑 `machine_id`，新增持久化黑名单；后续该机心跳 `reason:'blacklisted'` 直接降级）、`POST .../anomalies/:id/ignore`（误报/已处理）。
- **验收标准**：
  1. 5 类规则均能在模拟数据下被触发并出现在告警列表。
  2. 吊销/拉黑 在 audit 留痕；拉黑对后续心跳即时生效。
  3. 扫描在 500 台 × 心跳数据规模下 < 2s（或异步定时扫描 + 结果缓存，见待确认 #9）。

#### A4 远程管控指令通道　【P1】
- **描述**：定义服务端→客户端下行指令表与状态机（即使本期客户端仅模拟也要定义全）：
  - **指令表**：`restart_client`（重启客户端）、`disable_client`（禁用客户端，等同拉黑/吊销）、`disable_printer` / `enable_printer`（需 `printer_id`）、`push_notice`（公告）、`push_config`（下发配置片段）。
  - **通道与状态机**：服务端写入按 `machine_id` 的指令队列，状态 `{pending→sent→acked | timeout}`；客户端下次心跳携带 `ack_id` 回执；服务端在 `timeout`（如 2×心跳间隔）内未收到 ack 标记 `timeout`。
  - 提供 `POST /api/admin/fleet/clients/:machine_id/command`（下发，参数 `action+payload`）、`GET /api/admin/fleet/clients/:machine_id/commands`（指令历史与状态）；心跳请求体新增 `ack_id` 字段（旧客户端忽略）。
- **验收标准**：
  1. 指令表与状态机文档化（作为协议规范交付）。
  2. 服务端在模拟客户端下完成「下发→（模拟 ack）→acked」全流程，超时自动标记。
  3. 危险指令（`disable_client`/`restart_client`）需 L2+ 且 audit 留痕。

#### A5 规模化（非功能）　【P0】
- **描述**：以 500 台 × 心跳间隔（建议 60s，可配）为前提；心跳写入/聚合/列表/异常扫描的性能与存储设计。现有 `store.json` 全量同步写无法满足（每心跳写整文件），须改为：心跳快照独立存储（如 `fleet.json` 或 SQLite），批量/节流落盘，列表/聚合在内存索引完成。
- **验收标准**：
  1. 500 台 × 60s 心跳（≈8.3 req/s）下，心跳接口 p99 < 100ms，不阻塞主流程。
  2. 客户端列表/详情/聚合/异常扫描满足 A2/A3 阈值。
  3. 提供心跳间隔与离线阈值配置项。

#### A6 通信地址参数化　【P0】
- **描述**：新增 `configManager` 字段 `externalEndpoint`（外网/穿透基址，如 `https://tunnel.example.com:3457`）与 `internalEndpoint`（内网，如 `http://10.0.0.11:3457`）；客户端心跳/指令等对外地址统一引用该配置，后续替换穿透地址只改配置不改代码。前端「部署物料」展示当前生效 `externalEndpoint` + `publicKey` 供客户端写入。
- **验收标准**：
  1. 配置项存在且可在「配置」Tab 修改、重启或即时生效。
  2. 客户端 agent 启动/心跳地址读取自配置；文档说明替换流程。
  3. `externalEndpoint` 为空时前端提示尚未配置穿透，缺省回退 `internalEndpoint`。

### B. 页面合并与美化

#### B1 合并 console.html + admin.html 为单一控制台页　【P0】
- **描述**：以 `console.html` 侧栏结构为骨架，将 `admin.html` 能力并入并去重：新建「集群 / 打印机 / 异常」Tab（对应 A）；保留/补齐「许可证」能力（发放激活码 / 激活码列表+吊销 / 已激活许可证 / 部署物料公钥）；保留「订单·会员 / 管理员 / 配置 / 系统状态」。下线独立 `admin.html`（保留 `/admin` 重定向到 `/console` 或直接 404，见待确认 #6）。
- **验收标准**：
  1. 单一页面覆盖原 console + admin 全部功能，无遗漏（逐项检核：`issueCode`、codes+revoke、licenses、orders、admins、config、system/audit、pubkey）。
  2. 原 `admin.html` 的激活码发放/吊销在合并页可用。
  3. 两个独立 URL 处理符合待确认 #6 决策。

#### B2 套用 config.html 专业后台风格　【P0】
- **描述**：合并页采用 `config.html` 已落地的统一主题（专业后台、暗色/统一变量、卡片化、表格化）。统一色彩变量、卡片、表格、标签(tag)、按钮、弹窗、toast；废弃 `admin.html` 的简陋内联样式。
- **验收标准**：
  1. 合并页各 Tab 视觉风格一致（色彩/间距/卡片/表格/标签统一）。
  2. 与 `config.html` 视觉语言一致（同一套 CSS 变量或派生）。

#### B3 配置中心作为「配置」Tab 并入　【P0】
- **描述**：复用 `lib/configManager.js` 与 `console.html` 已有的 `/api/admin/console/vars` 渲染逻辑，作为合并页「配置」Tab（`console.html` 已存在该 Tab，需确保从 `config.html` 单页切换后无功能损失）。`/admin/config` 单页保留重定向或下线（见待确认 #6）。
- **验收标准**：
  1. 「配置」Tab 完整呈现 23 字段、分组、即时生效/需重启提示、保存审计。
  2. 原 `config.html` 能力（分组编辑、保存、`restartRequired` 提示）在 Tab 中等价可用。

#### B4 合并页新增「集群 / 打印机 / 异常」视图　【P0】
- **描述**：对应 A 的展示层（详见第 4 节 UI 设计稿）：
  - **集群**：总览卡片（在线/离线/异常/总数）+ 客户端表格（machine_id, 版本, 公网IP, 地区, CPU/内存, 开机, 最近心跳, 状态）+ 筛选/搜索/分页 + 详情（心跳历史、打印机、授权、快照、远程指令面板）。
  - **打印机**：聚合表（打印机名, 客户端, 状态, 纸量/墨量, 最近打印, 在线）+ 筛选/搜索 + 行内「禁用」等远程指令按钮。
  - **异常**：告警列表（规则, 客户端, 原因, 严重级, 时间）+ 处置按钮（吊销/拉黑/忽略）。
- **验收标准**：
  1. 三视图数据来自 A2/A3 接口，分页/筛选/搜索可用。
  2. 集群/详情/打印机/异常之间可互跳转（如异常→对应客户端详情）。
  3. 危险操作有确认弹窗 + L2+ 限制 + toast 反馈。

## 5. 待确认问题（务必澄清）

1. **客户端 agent 是否本期真写代码部署，还是只定义协议 + 服务端用模拟数据？**（关键，影响工作量巨大；架构铁律：外网客户端二进制不可改，假设 agent=可部署配套程序；若不碰客户端侧则只做服务端模拟 + 协议定义。）
2. **心跳上报频率与数据量**（500 台 × 周期，建议 60s 可配；心跳体体积受 `printers[]` 规模影响）。
3. **打印机状态字段到底要哪些**（`online/offline/paper_out/jam/paper_level/ink_level/last_print_at` 等），客户端能否提供；墨量/纸量是否每台都有。
4. **异常授权「拉黑 machine_id」的持久化与生效机制**（现有吊销是 license 维度；机器维度拉黑是否新增 store 黑名单 + 心跳 `reason:'blacklisted'`）。
