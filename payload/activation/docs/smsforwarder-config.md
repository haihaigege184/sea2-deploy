# SmsForwarder 微信收款通知转发配置（用户侧）

本文档给你一份「可直接照抄」的 SmsForwarder（短信转发器）App 配置，用于把**微信收款通知**自动推送到 sea1 激活服务器，实现「用户付款 → 自动激活」。

> 适用通道：**微信**（个人收款码）。支付宝当面付保持原样不变，无需此配置。

---

## 0. 前置条件

1. 激活服务器已部署并监听（默认端口 `3457`），且与手机在**同一局域网**（或服务器有公网可达地址）。
2. 服务端已设置环境变量 `WEBHOOK_SECRET`（强随机串）。本转发规则 URL 里的 `secret=` 必须与之**完全一致**。
3. 已安装官方 SmsForwarder（下载见 `smsforwarder-apk.md`）。

---

## 1. 新建转发规则（步骤）

打开 SmsForwarder →「转发规则」→「添加规则」：

### 1.1 基本信息
- **规则名称**：`sea1 微信收款`
- **启用**：✔ 打开

### 1.2 监听过滤（只转发微信收款通知，避免无关短信/通知刷屏）
- **监听应用**：`com.tencent.mm`（微信）
- 在「过滤条件」里二选一配置（推荐都加上，更精准）：
  - **关键词过滤（包含）**：`收款通知` `微信支付` `¥` `收到`
  - **正则过滤（匹配）**：下方「正则示例」中的规则

### 1.3 转发方式（核心）
- **转发类型**：`HTTP 请求`（HTTP 对接 / webhook）
- **请求方法**：`POST`
- **URL**（把 `<WEBHOOK_SECRET>` 换成你服务端真实值，`10.0.0.11` 换成你服务器局域网 IP 或域名）：

```
http://10.0.0.11:3457/api/v1/webhook/wechat?secret=<WEBHOOK_SECRET>
```

> 若服务器在公网或有 HTTPS 反代，把 `http://10.0.0.11:3457` 换成对应 `https://你的域名` 即可，路径与 `?secret=` 不变。

### 1.4 请求头（Header）
一般留空即可。服务端主路径用 `?secret=` 验签。
- （可选）若希望额外做 HMAC 校验，可加头 `X-Signature: <HMAC-SHA256(rawBody, WEBHOOK_SECRET) 的 hex>`，服务端会校验（缺失则不强制）。

### 1.5 请求体（Body）模板

> ⚠️ **踩坑必读（已实测栽过两次）**：SmsForwarder 的变量标签是**固定集合、大小写敏感、且必须用双花括号 `{{...}}`**。
> 它**只替换自己认识的标签**，不认识的标签会**原样发出**——于是服务器收到的就是模板字面量而不是真实通知。
> 下面这些**曾经用错、确认无效**的写法，请勿再用：
> - `{{packageName}}` / `{{content}}` / `{{title}}` / `{{from}}` / `{{timestamp}}`（这不是 SmsForwarder 的标签名）
> - `{内容}` / `{包名}` 等单花括号写法（语法应为**双**花括号）
>
> 官方变量清单：<https://github.com/pppscn/SmsForwarder/wiki/附录3：自定义模板可用变量>
> 结论：**标签名必须一字不差地用官方英文名（大写），且双花括号**。

推荐发送「原始通知 JSON」，让服务端字段无关解析更稳。**原样**把下面的内容粘进 Body：

```json
{
  "packageName": "{{PACKAGE_NAME}}",
  "title": "{{TITLE}}",
  "content": "{{MSG}}",
  "from": "{{PACKAGE_NAME}}",
  "timestamp": "{{RECEIVE_TIME}}"
}
```

标签含义（APP 通知场景）：
| 标签 | 替换成的真实值 | 说明 |
|------|---------------|------|
| `{{PACKAGE_NAME}}` | 应用包名（微信=`com.tencent.mm`） | 用于识别来源 |
| `{{TITLE}}` | 通知标题（如「微信支付收款通知」，可能为空） | |
| `{{MSG}}` | **通知正文** | 🔑 收款金额与 `SEA1-订单号` 都在这里，服务端靠它抽金额/单号 |
| `{{RECEIVE_TIME}}` | 收到时间 | 排查用 |

> **版本要求**：上述标签需 **SmsForwarder ≥ v3.3.1**（`{{RECEIVE_TIME}}` 为 v3.3.1+ 新增；旧版标签名不同）。
> 建议「关于」页开启预览体验计划、升级到每周构建版以获得完整标签集。
>
> 如果你只想要纯文本，也可以把 Body 直接设为 `{{MSG}}`（单行文本），服务端仍能抽出金额与订单号。但 JSON 更稳，推荐用上面的模板。

### 1.6 保存并测试
- 保存规则。
- 用另一个微信号给你「付款 ¥X.XX」，并在**转账备注**里填写订单号 `SEA1-xxxxxxxx-XXXXXX`（可选；不填也能靠金额匹配）。
- 观察 SmsForwarder 日志是否成功 POST；服务端日志出现订单 `paid` 即成功。

## 2. 正则 / 关键词示例（可直接复制）

### 关键词（包含任一即转发）
```
收款通知
微信支付
¥
收到
```

### 正则（匹配「微信支付 / 收款通知」类标题，且内容含金额）
```
标题正则：微信支付|收款通知|微信转账
内容正则：¥\s?\d+(\.\d{1,2})?|收到
```

> 说明：服务端并不依赖这些字段名，它会对整条通知做「字段无关」解析——只要文本里出现 `¥金额` 和/或 `SEA1-订单号`，就能正确抽取。上面的过滤只是为了**减少无关通知的转发量**。

### 结构化过滤条件（推荐）

SmsForwarder 的「过滤条件」是一个结构化 UI，用 `并且 / 是 / APP包名 / 通知标题 / 通知内容 / 包含 / 相等` 这类 DSL 拼条件。**正确做法：标题命中即「全量转发」，内容筛选交给激活服务器去做判断**——在这里不要做任何通知内容过滤。

推荐写法（标题精确命中即全转发）：

```
并且 是 APP包名 相等 com.tencent.mm
并且 是 通知标题 相等 微信收款助手
```

**真机标题兼容提示**：若你真机收到的通知标题实际是 `微信支付收款通知` 而非精确的 `微信收款助手`，请把第二行改成更宽松的包含匹配更稳：

```
并且 是 通知标题 包含 微信收款
```

建议先试 `相等`，匹配不到再换成 `包含`。**无论如何都不要加任何「通知内容」过滤条件**（例如「包含 元」「包含 sea」），否则会漏掉真实回执。

**原错误写法（请勿照抄）的两个坑：**
1. **粘连接词**：写成 `并且 是 通知内容 包含 微信支付收款并且 是 通知内容 包含 元……` 会把连接词 `并且` 直接粘到值 `微信支付收款` 后面，导致前半条件恒为假（整条规则左半边永远不成立）。
2. **漏掉真实回执**：真实微信收款回执是 `微信支付收款 ¥5.00`（只有 `¥`，既没有「元」也没有「sea」）。一旦按「内容含 元 / 含 sea」过滤，真实付款会被整条规则漏掉；整条过滤退化成「内容含 sea」，既与标题脱钩、也与付款无关。

## 3. 服务端如何识别（给好奇的你）

服务端收到后：
1. **验签（fail-closed）**：`?secret=` 缺失/不符 → 直接 `401`，不处理。
2. **字段无关解析**：递归扫描整条 JSON/文本，抽金额（兼容 `¥` / `￥` / 千分位 / `N元`）与订单号（`SEA1-` 前缀）。
3. **匹配订单**：
   - 若通知里有 `SEA1-订单号` → 按订单号强匹配；
   - 否则 → 按金额匹配（仅限微信通道、待支付态订单；金额带唯一化偏移，确保不串单）。
4. **标记已支付（幂等）**：成功后订单变 `paid`，bot 随即发 license。重复推送不会重复发码。

## 4. 排错

| 现象 | 排查 |
|------|------|
| 服务端返回 `401 invalid webhook secret` | URL 里的 `secret=` 与服务端 `WEBHOOK_SECRET` 不一致；或漏填。 |
| 服务端返回 `200` 且 `matched:true` | 匹配成功，订单已标记 `paid`，bot 自动发 license。✅ 链路打通。 |
| 服务端返回 `200` 且 `matched:false, reason:"no_order_found"` | 接口已通、密钥正确，但没匹配到订单：多半是付款金额/订单号与系统里 pending 订单对不上，或订单已超时（30 分钟）。在群里发 `#推送查询 5` 看收到的原文，确认真实内容是否正确进来。 |
| 服务端返回 `200` 且 `matched:false, reason:"amount_mismatch"` | 解析出订单号但金额对不上（转账金额填错或偏移错位）。检查实际付款金额。 |
| 服务端收到的是模板字面量（如 `{{MSG}}`、`{内容}`） | SmsForwarder 变量标签写错：必须用去**双花括号 + 官方英文名**（如 `{{MSG}}`）。见 1.5 节。 |
| SmsForwarder 日志成功但用户没激活 | 确认 bot 侧：用户付款后仍需在 bot 里发「已支付 <订单号>」（会立即检测到 paid 并自动发 license）；或运维已配置 `BOT_NOTIFY_URL` 全自动回调。 |
| 手机与服务器不在同一局域网 | 用服务器公网地址 / 内网穿透（如 cloudflared）替换 URL 中的 IP。 |

---

## 5. 安全提醒

- `WEBHOOK_SECRET` 等同于「可标记付款」的凭据，**务必强随机、不泄露、不写进代码仓库**。
- 该 webhook 仅用于标记「已支付」并触发发码；金额匹配有唯一化偏移 + 容差保护，且重复推送幂等，不会被重复发码。
- 支付宝当面付路径完全独立，不受此配置影响。
